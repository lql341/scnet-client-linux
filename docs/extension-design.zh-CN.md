# 扩展设计

本文描述 Linux 构建在移植之外的增强：账户与额度信息、账单、作业监控、传输可见性、诊断以及
主题切换。文中确定实现机制、数据路径与边界，实现按此分阶段落地。

## 1. 约束

本仓库不修改厂商 `app.asar`。因此新增内容仅限以下三类：

- 放置在 `dist/` 下的一个脚本与一份样式表，由 `scripts/patch-vendor.cjs` 注入两个 HTML 入口；
- 厂商 preload 已经暴露的渲染层到主进程桥（`window.host`）；
- 由 `scripts/build-linux.sh` 组装进包内的文件。

由此产生三点设计约束。扩展无法新增主进程行为，因此不提供托盘角标、协议处理器或新的窗口类型；
扩展无法依赖厂商类名，这些类名经过压缩且随版本变化；扩展必须具备失效即退出的能力，某个宿主操作
消失时相关模块自行停用，客户端保持厂商原有行为。

## 2. 实现机制

```text
dist/scnet-ext/main.js        入口、模块注册表、桥接封装
dist/scnet-ext/theme.css      主题变量，按属性选择器生效
dist/index.html              登录界面补丁追加的 <script> 标签
dist/compat/index.html       同上，用于旧版渲染层
```

`main.js` 按功能拆分为模块。每个模块声明所需的宿主操作，注册表在启动时探测一次；探测失败的
模块直接跳过，控制台仅留一条告警。所有模块包裹在异常处理中：挂载期抛错时移除自身 DOM，不影响
应用外壳。

桥接沿用既有 preload 接口：

```js
window.host.invoke(operation, payload)   // 主进程校验，失败时以错误码 reject
window.host.on(event, handler)           // 宿主事件，返回取消订阅函数
window.host.context                      // { platform, arch, version, isMainWindow }
```

## 3. 数据路径

主进程已将平台客户端的读接口统一为一个操作 `scnet.read`，按资源划分方法。金额、标识与时间按平台
返回值透传，扩展只做格式化与展示，不落盘缓存。

| 界面 | 操作 | 方法 / 载荷 | 刷新策略 |
| --- | --- | --- | --- |
| 账户与额度卡片 | `scnet.read` | `account.get` | 60 秒，以及窗口获得焦点时 |
| 账单列表 | `scnet.read` | `billing.list`，带分页 | 打开时，支持手动刷新 |
| 账单明细 | `scnet.read` | `billing.get` | 选中时 |
| 作业列表与状态 | `scnet.read` | `jobs.list`、`jobs.get` | 面板打开时每 30 秒 |
| 作业指标 | `scnet.read` | `jobs.metrics` | 按需 |
| 传输与文件任务 | `scnet.read` | `transfers.list`、`file-tasks.list` | 可见时每 15 秒 |
| 分中心用量 | `scnet.read` | `usage.centers`（待平台提供），回退到 `account.get` | 60 秒 |
| 控制台页面 | `auth.open-authenticated-route` | `{ route }` | 事件触发 |
| 诊断信息 | `diagnostics.list-files`、`diagnostics.read-file`、`app.get-version`、`environment.get-context` | 按宿主定义 | 按需 |
| 任务通知 | `notifications.set-task-state` | `{ tasks: [...] }` | 状态变化时 |

写操作（取消作业、传输、订单）在第一版中不纳入范围。这类操作经过厂商的审批流程
（`operations.approve`），扩展若不复刻厂商逻辑则无法驱动该流程。

## 4. 功能

### 4.1 分中心用量

面板按中心回答三个问题：账户属于哪些中心、每个中心包含哪些集群、在该中心的消耗情况。

数据来自两种载荷。`account.get` 现已可用，返回钱包余额、赠送余额与按集群账户列出的条目，其中
`centerNames` 与 `clusterIds` 为平行数组；模块将其展开为「一个中心一行」，账户余额只在账户层面
呈现一次。`usage.centers` 是平台侧正在补充的消耗数据接口，面板已按其形状实现：

```json
{ "currency": "CNY",
  "centres": [
    { "centerName": "华东一区【昆山】", "clusterIds": ["11250"],
      "cpuCoreHours": 1234.5, "gpuCardHours": 87.25, "storageGiB": 512, "jobCount": 42 } ] }
```

平台未返回的字段显示为破折号；该载荷上线后表格自动增加消耗列，客户端无需改动。在此之前面板明确
标注分中心接口尚未开放，使限制可见而非隐含。

### 4.2 账单面板

由账户卡片打开：分页列表，每行对应一份账单，字段按平台返回内容呈现。选中行后调用 `billing.get`
填充明细区。导出在渲染层将已加载页面写为 CSV，不上传、不存储。

### 4.3 作业监控

列出排队与运行中的作业，显示状态、队列、已用时间与退出码。作业由运行转为完成、失败或取消时，通过
渲染层 `Notification` 接口弹出桌面通知，并同步到厂商任务指示器
（`notifications.set-task-state`）。托盘角标需要主进程支持，不在本设计范围内。

### 4.4 传输可见性

展示进行中的上传与下载，含方向、大小与进度，数据取自 `transfers.list` 与 `file-tasks.list`。
第一版为只读面板。

### 4.5 入口与控制台链接

面板从头像展开的账户菜单进入，位于「我的资源」与「费用中心」之后：用量与账单、传输任务、连接诊断、
主题。该菜单由厂商在每次展开时重新渲染，样式以 `data-v` 属性做作用域隔离，因此注入项从既有条目上
复制该属性，而不硬编码哈希；`MutationObserver` 保证每次展开只插入一次，位置在「退出登录」之前。

同一菜单承载渲染层已有的控制台目标：费用总览、资源中心、资源申请、反馈与个人信息。

账户卡片承载渲染层已有的控制台目标：费用总览、资源中心、资源申请、反馈与个人信息。每项为一个
路由字符串，交由 `auth.open-authenticated-route` 换取控制台会话后在默认浏览器打开。OpenAPI 控制台
在平台侧确认路由、并确认令牌重定向对该路由生效后并入同一列表。

### 4.6 诊断

一次操作生成测试期问题报告：客户端与 Electron 版本、平台与会话类型、启动器所做的沙箱判定、连接器
与技能数量、`diagnostics.read-file` 返回的最后 200 行日志，以及 4.7 节的连通性结果。报告可复制到
剪贴板或另存为文件，内容不上传。

### 4.7 连通性自检

对 `api.scnet.cn`、`www.scnet.cn` 与下载站点分别发起 HEAD 请求，各自三秒超时，报告状态码、时延与
生效的代理配置。该检查用于区分客户端故障与网络不可达，这两类在测试前期最容易混淆。

## 5. 主题

主题由 CSS 自定义属性覆盖与少量结构规则组成，由扩展应用，并从账户菜单切换。厂商默认样式保留为
`system`。

| 变量 | `system` | `paper` | `claude` |
| --- | --- | --- | --- |
| 画布 | 厂商 | `#FBFAF7` | `#FAF9F5` |
| 表面 | 厂商 | `#FFFFFF` | `#F0EEE6` |
| 文本 | 厂商 | `#1C1B1A` | `#141413` |
| 次级文本 | 厂商 | `#6B6862` | `#6C6A64` |
| 强调色 | 厂商 | `#2F6FEB` | `#D97757` |
| 边框 | 厂商 | `#E4E1DA` | `#E5E2D9` |
| 圆角 | 厂商 | 8 px | 12 px |

`claude` 主题采用 Claude 桌面客户端的比例关系：暖白画布、沙色表面、近黑文字、陶土色强调、较大的
圆角、一像素暖色边框，标题在厂商已使用展示字体处改为衬线字体。

规则绑定变量而非厂商工具类，厂商重构时主题降级为默认外观，不会破坏布局。选择结果存放在
`localStorage`（`scnet.ext.theme`），由 `<head>` 中的内联脚本在首帧前应用，避免闪烁。
`prefers-color-scheme` 仅驱动 `system`；两个显式主题为固定浅色主题。

渲染层在运行时将 `--color-accent`、`--color-accent-hover` 与字体栈以内联样式写入 `<html>` 与
`<body>`。普通权重的样式表规则无法覆盖内联声明，因此强调色在两个元素上以 `!important` 声明；
其余变量交由层叠处理，厂商仍可自由调整自身取值。

正文对比度维持 4.5:1 以上，强调色对画布维持 3:1 以上；焦点环取自强调色变量，在各主题下均可见。

## 6. 配置与打包

扩展是 `app.asar` 内的单个目录，采用打包而非解包形式：不含原生代码，无运行时依赖。
`SCNET_EXT_DISABLE=1` 用于排障时整体停用，`scnet.ext.*` 下的 `localStorage` 键保存主题与面板偏好，
此外不写入任何数据。

## 7. 验证方案

在 Ubuntu 26.04.1 x64/X11 上针对 4.1.1 包执行，使用 DevTools 协议并采用既有配置的副本。

| 范围 | 方法与结果 |
| --- | --- |
| 扩展加载 | `window.__scnetExt` 存在，启动按钮已挂载，样式表生效 |
| 分中心用量 | 1 个账户展开为 12 行（华东一区【昆山】、西北二区【甘肃】等），并显示钱包与赠送余额；`usage.centers` 被宿主 schema 拒绝，回退路径生效并在面板中注明 |
| 账单 | 加载 20 行，总数 612，无错误；分页与 CSV 导出绑定到已加载行 |
| 诊断 | 生成 12,270 字符的报告，含平台、版本、主题与日志尾部 |
| 主题 | `claude` 解析为画布 `#faf9f5`、强调 `#d97757`、边框 `#e5e2d9`、圆角 12 px；侧栏背景实测 `rgb(240, 238, 230)` |
| 失败路径 | 平台拒绝凭据状态时，面板显示 `SCNet account information is unavailable`，外壳不受影响 |

未验证：状态迁移时的通知投递（测试期间未出现作业状态变化）、已加载行之外的 CSV 内容，以及不属于
本范围的 OpenAPI 控制台路由。

## 8. 边界

第一版不纳入范围的内容及原因：

- 托盘角标与托盘菜单：仅主进程可实现；
- `scnet://` 深链：需要在主进程调用 `setAsDefaultProtocolClient`；
- 内嵌控制台页面：需要共享会话的新窗口；
- 作业提交与取消界面：需要厂商审批流程；
- 原生标题栏主题：Linux 上无主进程挂钩。

## 9. 实现状态

本仓库已实现：注入补丁、模块注册表、含回退的分中心用量、账单面板与 CSV 导出、作业通知轮询、
诊断报告，以及三套主题。平台侧待提供：4.1 节所述的 `usage.centers` 载荷。移除该补丁即整体停用；
某个宿主操作消失时，相关模块单独停止。
